# Raffle Link Platform
### سامانه مدیریت لینک‌های اختصاصی قرعه‌کشی

این پروژه با Laravel پیاده‌سازی شده و هدف آن ایجاد لینک اختصاصی برای شرکت‌کنندگان در قرعه‌کشی است. هر لینک یک توکن تصادفی و امضای رمزنگاری‌شده دارد. اعتبار لینک پیش از ارسال درخواست به Laravel در Nginx بررسی می‌شود و ثبت اطلاعات شرکت‌کنندگان نیز با استفاده از قید یکتای دیتابیس انجام می‌گیرد.

تمرکز اصلی پیاده‌سازی روی سه موضوع است: اعتبارسنجی لینک، جلوگیری از ثبت‌نام تکراری و مدیریت درخواست‌های هم‌زمان.

## امکانات اصلی

- تولید لینک اختصاصی با توکن تصادفی ۱۲۸ بیتی و قالب Base64URL.
- امضای لینک با الگوریتم HMAC-SHA-256 و خروجی ۱۲۸ بیتی.
- بررسی اعتبار مسیر و امضا در Nginx با استفاده از ماژول njs.
- جلوگیری از ارسال درخواست‌های دارای لینک نامعتبر به Laravel و PHP-FPM.
- بررسی مجدد اعتبار لینک و وضعیت قرعه‌کشی در سمت Laravel.
- جلوگیری از ثبت چندباره یک شماره همراه در یک قرعه‌کشی با قید یکتای دیتابیس.
- تولید گروهی لینک‌ها با عملیات دسته‌ای ۵۰۰تایی.
- استفاده از Redis برای cache و محدودسازی نرخ درخواست‌ها.
- ارائه API مدیریتی با احراز هویت Bearer Token.
- تست‌های واحد و ویژگی برای بخش‌های اصلی برنامه.

## فناوری‌ها و پیش‌نیازها

| بخش | فناوری یا نسخه |
|---|---|
| Backend | PHP 8.3+ |
| Framework | Laravel 13 |
| Dependency Manager | Composer 2 |
| Database | MySQL 8+ یا MariaDB سازگار |
| Cache و Rate Limiting | Redis |
| Web Server | Nginx |
| Nginx JavaScript | njs 0.9.1+ با QuickJS و پشتیبانی HMAC |
| Testing | PHPUnit و Node.js |

برای اجرای محلی می‌توان از SQLite استفاده کرد. در محیط عملیاتی، MySQL و Redis گزینه‌های در نظر گرفته‌شده برای ذخیره‌سازی و مدیریت درخواست‌ها هستند.

## نصب و راه‌اندازی

ابتدا مخزن را دریافت کنید:

```bash
git clone https://github.com/daniyal3y/Programing-web.git
cd Programing-web/raffle-link-platform
```

وابستگی‌های PHP را نصب کنید:

```bash
composer install
```

فایل تنظیمات محیط را بسازید:

```bash
cp .env.example .env
php artisan key:generate
```

### تنظیم کلید امنیتی لینک‌ها

برای امضای لینک‌ها، برنامه از یک secret مشترک بین Laravel و Nginx استفاده می‌کند. این مقدار باید تصادفی و محرمانه باشد.

برای ساخت آن:

```bash
php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"
```

مقدار تولیدشده را در فایل `.env` قرار دهید:

```dotenv
RAFFLE_LINK_SECRET=YOUR_GENERATED_SECRET
```

برای `RAFFLE_ADMIN_TOKEN` نیز یک مقدار تصادفی مستقل انتخاب کنید. این دو مقدار نباید در Git ثبت شوند یا در اختیار کاربران قرار بگیرند.

### تنظیم دیتابیس برای توسعه

در صورت استفاده از SQLite، ابتدا فایل دیتابیس را ایجاد کنید و تنظیمات زیر را در `.env` قرار دهید:

```dotenv
DB_CONNECTION=sqlite
DB_DATABASE=/absolute/path/to/project/database/database.sqlite

CACHE_STORE=array
QUEUE_CONNECTION=sync
SESSION_DRIVER=array
```

مسیر دیتابیس باید با مسیر واقعی پروژه در سیستم شما مطابقت داشته باشد.

سپس migrationها و seedها را اجرا کنید:

```bash
php artisan migrate --seed
```

برای اجرای برنامه در محیط توسعه:

```bash
php artisan serve
```

## API مدیریتی

مسیرهای مدیریتی با Bearer Token محافظت شده‌اند. برای ارسال درخواست باید هدر زیر وجود داشته باشد:

```http
Authorization: Bearer YOUR_ADMIN_TOKEN
```

### ۱. ایجاد قرعه‌کشی

```http
POST /api/admin/raffles
Content-Type: application/json
Authorization: Bearer YOUR_ADMIN_TOKEN
```

نمونه بدنه درخواست:

```json
{
  "name": "قرعه‌کشی پاییز",
  "is_active": true,
  "starts_at": null,
  "ends_at": null
}
```

### ۲. تولید لینک‌های اختصاصی

پس از ایجاد قرعه‌کشی می‌توان برای آن لینک تولید کرد:

```http
POST /api/admin/raffles/1/links
Content-Type: application/json
Authorization: Bearer YOUR_ADMIN_TOKEN
```

نمونه درخواست:

```json
{
  "quantity": 1000,
  "expires_at": null
}
```

پاسخ API شامل تعداد لینک‌های صادرشده (`issued`) و آرایه لینک‌های تولیدشده است.

تعداد لینک در هر درخواست حداکثر ۱۰٬۰۰۰ عدد است. تولید لینک‌ها به‌صورت دسته‌ای انجام می‌شود تا حجم عملیات در هر مرحله کنترل شود.

## ساختار لینک و اعتبارسنجی امنیتی

ساختار لینک‌های اختصاصی به شکل زیر است:

```text
/r/{token}.{signature}
```

برای نمایش صفحه ثبت‌نام و اطلاعات شرکت‌کننده، مسیر زیر نیز در نظر گرفته شده است:

```text
/r/{token}.{signature}/entries
```

در این ساختار، `token` شناسه تصادفی لینک و `signature` امضای تولیدشده با HMAC است.

### مراحل بررسی درخواست در Nginx

اعتبارسنجی اولیه در فایل زیر انجام می‌شود:

```text
nginx/njs/raffle_guard.js
```

ترتیب کار به این صورت است:

1. مسیر درخواست از نظر ساختار و قالب بررسی می‌شود.
2. توکن و امضای موجود در URL استخراج می‌شوند.
3. Nginx با استفاده از secret مشترک، امضای مورد انتظار را محاسبه می‌کند.
4. امضای دریافتی با مقدار محاسبه‌شده مقایسه می‌شود.
5. اگر مسیر یا امضا معتبر نباشد، پاسخ 404 مستقیماً از Nginx برگردانده می‌شود.
6. تنها درخواست‌هایی که از این مرحله عبور کنند به Laravel ارسال می‌شوند.

این روش باعث می‌شود درخواست‌های دارای مسیر یا امضای نامعتبر، پیش از ورود به چرخه پردازش Laravel متوقف شوند.

Laravel نیز بررسی را به Nginx واگذار نمی‌کند؛ اعتبار امضا و وضعیت لینک در سمت برنامه مجدداً بررسی می‌شود.

**نکته:** این سازوکار درخواست‌های مربوط به مسیرهای تحت کنترل برنامه، یعنی `/r/...`، را بررسی می‌کند. تغییر دامنه، DNS یا مقصد شبکه خارج از محدوده اعتبارسنجی مسیر در این virtual host است. همچنین امضای ۱۲۸ بیتی HMAC احتمال جعل بسیار ناچیزی دارد، اما از نظر ریاضی احتمال آن صفر نیست.

### تنظیم Nginx

نمونه پیکربندی در این فایل قرار دارد:

```text
nginx/nginx.conf.example
```

برای استفاده در سرور باید موارد زیر با محیط مقصد هماهنگ شوند:

- نصب و فعال‌سازی `ngx_http_js_module` و نسخه سازگار njs.
- اطمینان از پشتیبانی runtime از QuickJS و `crypto.createHmac`.
- تنظیم مسیر فایل `raffle_guard.js`.
- قرار دادن secret مشترک در محیط سرویس Nginx.
- تنظیم مسیر پروژه، دامنه و socket مربوط به PHP-FPM.
- جلوگیری از دسترسی عمومی به فایل‌های `.env`، `vendor`، `storage` و فایل‌های مخفی.

پس از انجام تنظیمات، پیکربندی را بررسی و Nginx را بارگذاری مجدد کنید:

```bash
sudo nginx -t
sudo systemctl reload nginx
```

در صورت خالی یا نامعتبر بودن secret، اعتبارسنجی لینک‌ها به‌صورت fail-closed عمل می‌کند؛ یعنی درخواست‌ها پذیرفته نمی‌شوند و پاسخ 404 دریافت می‌کنند.

## جلوگیری از ثبت‌نام تکراری

یکی از بخش‌های مهم پروژه، جلوگیری از ثبت چندباره یک شماره همراه برای یک قرعه‌کشی است.

صرفاً بررسی شماره با یک دستور `SELECT` و سپس اجرای `INSERT` کافی نیست؛ چون ممکن است دو درخواست هم‌زمان هر دو شماره را آزاد تشخیص دهند و هر دو اطلاعات را ثبت کنند.

برای جلوگیری از این وضعیت، جدول `raffle_entries` دارای قید یکتای مرکب روی دو ستون زیر است:

```text
(raffle_id, phone)
```

عملیات ثبت نیز با `insertOrIgnore` انجام می‌شود. در نتیجه، تصمیم نهایی درباره یکتا بودن اطلاعات بر عهده دیتابیس است و درخواست تکراری نمی‌تواند یک رکورد دوم با همان ترکیب قرعه‌کشی و شماره همراه ایجاد کند.

شماره همراه باید پیش از ثبت به قالب استاندارد بین‌المللی E.164 تبدیل شود. برای مثال:

```text
+989121234567
```

این کار از ثبت یک شماره با چند قالب نوشتاری متفاوت جلوگیری می‌کند.

## مدیریت درخواست‌ها و کارایی

برای کاهش پردازش‌های غیرضروری و کنترل درخواست‌های پرتعداد، چند روش در پروژه استفاده شده است:

- جست‌وجوی توکن با ایندکس یکتا به‌جای جست‌وجوی بدون ایندکس.
- نگهداری موقت اطلاعات لینک در Redis با TTL پیش‌فرض ۳۰ ثانیه.
- محدودسازی نرخ درخواست در Nginx پیش از ورود به PHP.
- استفاده از rate limiter توزیع‌شده در Laravel.
- تولید گروهی لینک‌ها با batchهای ۵۰۰تایی.
- متوقف کردن درخواست‌های نامعتبر در لایه Nginx.
- استفاده از هدرهای `no-store` و `no-referrer` برای کاهش ذخیره‌سازی و نشت اطلاعات مربوط به لینک خصوصی.

در استقرار چندسروری، secret باید در تمام سرورها یکسان باشد و Redis و دیتابیس نیز به‌صورت مشترک و سازگار پیکربندی شوند.

اگر غیرفعال‌کردن لینک باید سریع‌تر از زمان انقضای cache اعمال شود، لازم است TTL کاهش یابد یا کلید cache مربوط به آن لینک هنگام تغییر وضعیت پاک شود.

## اجرای تست‌ها

برای اجرای تست‌های Laravel:

```bash
php artisan test
```

برای اجرای تست مربوط به اعتبارسنجی مسیر و امضای لینک در Node.js:

```bash
node --experimental-default-type=module tests/nginx/raffle_guard.node-test.mjs
```

تست‌های پروژه بخش‌هایی مانند تولید و اعتبارسنجی امضا، تغییر توکن و signature، دسترسی به API مدیریتی، ایجاد لینک و جلوگیری از ثبت رکورد تکراری را پوشش می‌دهند.

تست Node.js رفتار کد guard را بررسی می‌کند؛ برای اطمینان از عملکرد واقعی Nginx باید تست جداگانه روی سروری انجام شود که ماژول njs روی آن نصب و فعال است.

## نکات امنیتی و استقرار

پیش از انتشار روی سرور عملیاتی، این موارد را بررسی کنید:

- مقادیر secret و توکن مدیریتی را با مقادیر تصادفی و مستقل تنظیم کنید.
- فایل `.env` را در مخزن Git قرار ندهید.
- دسترسی عمومی به فایل‌های داخلی برنامه را مسدود کنید.
- Nginx و njs را با نسخه‌های سازگار نصب کنید.

- تست‌های Laravel و تست‌های مستقل Nginx را در محیط مقصد اجرا کنید.
- برای محیط عملیاتی از HTTPS استفاده کنید.
